# 项目研究与实现

研究日期：2026-11-14。三个项目均读取了实际源码；以下提交为本地研究快照，发布二进制另行锁定版本。

## OPlus-Tracker

仓库：https://github.com/JerryTse-OSS/OPlus-Tracker

研究提交：`bfc1e9780ece1bd17d8c43d592f5c32707b4c179`。

`tomboy_pro.py` 的核心是 `QueryConfig → process_ota_version → query_update → process_response`。机型、地区、公钥、nvCarrier、模式、OTA 版本通过请求头传入；GUID、组件基线、招募字段通过 AES-CTR 加密请求体传入。AES 密钥经 RSA-OAEP 封装。地区配置来自 `config.py`；有实际 GUID 或 PRE 时使用 `/update/v6`，普通查询使用 `/update/v3`。

全量查询不带组件基线；增量候选查询带 `name:componentVersion`。设备 `ro.oplus.version.base` 映射为 `system_vendor`，其余组件保持原名。是否真正包含增量操作仍需检查 payload，不能只看请求意图或包大小。实测响应 `componentPackets` 还包含 `vabInfo`、md5、size 和流式位置等信息；程序读取远程 ZIP/manifest 做独立验证。

上游自动补全 A/C/F/H/J 分支，anti 的实际行为是使用 taste，并对无结果请求尝试上一次成功的 fake OTA 版本。本工具保留这种探测思路，加入已发现版本的查询配方缓存，限制一次查询规模；限流时退避并停止连续受限请求。

README 与当前源码存在差异：文档列出的 `--gray`/`--graynew` 并非该研究提交实际解析的 CLI 参数；实际招募字段为 `recruitID`，请求体中传 `recruitId=whoami`。因此本工具通过真实 `QueryConfig` 接口接入，不拼接不存在的参数。请求通道不等于发布性质；对 `published + isRecruit=false` 的结果仍归正式版，字段不足则归通道待确认。

`downgrade_query.py` 使用 AES-GCM + RSA-OAEP，国区 query-v3 需要真实 DUID、项目号、SN。没有真实 DUID 时不会假造凭证，也不静默回退旧版无凭证接口。`C16_transer.py` 表明普通 downloadCheck 可通过 userId 和范围请求解析，PKI download 另需设备证书。本工具支持普通重定向，对需要 PKI 的地址明确报错。

采用上游 Python 文件作为可替换源模块。修改包括：包内相对导入；保留解密后的 raw_body；取消打印完整服务器响应；缩短并限制单次请求重试；重定向使用 stream 并关闭响应；降级查询恢复 TLS 证书验证。详见 vendor 目录的完整可修改源码。

## ssut/payload-dumper-go

仓库：https://github.com/ssut/payload-dumper-go

研究提交：`c3a50ba8d784764c06143c1f82971cd81a77f9d6`；使用发布版 **2.1.0 Windows amd64**。

`payload.Open` 读取本地 payload/ZIP，ZIP_STORED 直接定位，压缩 entry 解到临时文件。`cmd/root.go` 的 `-m -p -o -old` 提供机器进度、分区选择、目录和旧镜像输入。payload 层校验操作数据、基线与输出镜像，增量输出可重建 dm-verity hash tree/FEC。当前部分差分操作仍未支持，不应把任意增量固件宣称为可完整解包。

适合本地、增量及严格验证。工作台保持默认验证，不传 `-no-verify` 或 `-no-fec`。在线场景使用工作台的 HTTP Range 读取器，只取得所选操作数据并重新排布为临时 payload，再交给 ssut；文件不是可安装 OTA。每个目标镜像再次按 manifest 核验。

## xishang0128/payload-dumper-go

仓库：https://github.com/xishang0128/payload-dumper-go

研究提交：`3e50e4e38af6e60b139b4b29065778a1e73df2a2`；使用发布版 **v0.1.6 Windows amd64-v3**。

该分支拆分为 file reader、ZIP 定位、metadata、dumper、压缩和提取策略。file.NewHTTPFile 通过 HTTP Range 提供随机访问，支持在远端 ZIP 中按需读取 payload；CLI 分为 list、metadata、extract、extract-diff。

发布版本与 main 不完全一致：v0.1.6 的 extract 使用 `--workers`，没有 main 中的 `--cpu-count`、`--strategy`、`--verify`。已用实际发布二进制 `--help` 核验，工作台传发布版支持的参数，并自行核验目标哈希。CGO/纯 Go、v3 等构建差异不能忽略；自动模式运行失败可回退 ssut。

## ColorOS 官方助手与降级通道逆向研究

研究来源：官方 ColorOS 升级/降级助手逆向分析及对话研究（`4227916f-4fbf-49e8-a89a-a80cab893662`）。

- **伴生组件自适应检测**：ColorOS 11.3 之前与之后的系统更新组件广播接收策略存在分水岭。随包附带 `OTA_17.apk`（旧版专用，包名 `com.coloros.ota`，入口组件 `com.coloros.ota.UpgradeActivity`）与 `OTA_113.apk`（现代 ColorOS 11.3+ 专用，包名 `com.oplus.ota`，入口组件 `com.oplus.otaui.activity.EntryActivity`）。推送前根据设备的系统 SDK 及包名自动选择安装或跳过。
- **存储容量安全预检**：通过 `adb shell df -k /sdcard` 提取首行非虚拟挂载的可用 1K-blocks，避免因 `/sdcard` 剩余空间不足导致的大包推送中途失败。
- **安全核验机制**：推送前强制执行 `inspect_package_safety`，通过 payload manifest 深度验证固件适用代号与已连设备的匹配性，禁止跨机型强刷；拦截增量包用于降级；拦截破损小于 500MB 的文件。
- **参数注入与协议唤醒**：将固件包传输至手机 `/sdcard/Download/` 后，通过系统广播唤醒伴生服务，向 `content://com.oplus.ota.provider.DataSharedProvider` 插入本地 URI 并设置 `forbid_check_update=true`，随后调用 `am start -n ... -e InstallPackage ...` 直接唤起官方本地降级界面，手机无需 Root 与解 BL 锁即可弹出官方更新确认弹窗。

## 工作台架构

- `oplus_tool/adb.py`：通过指定 serial 执行 ADB 只读属性查询；品牌筛选；市场名、完整 OTA、槽位、NV 地区与项目号解析。NV 固件地区优先于用户界面语言。
- `oplus_tool/push.py`：固件包安全核检、伴生应用检测与安装、手机存储空间预检、ADB 可取消推送及官方系统更新安装拉起。
- `tracker.py`：查询计划、上游适配、发布性质分类、payload 核验、动态链接解析、指定包重查。查询配方不保存 GUID/DUID。
- `catalog.py`：SQLite 历史索引；身份包含机型、地区、发布性质、包类型、OTA、组件、基线、哈希及不带签名参数的 URL 路径。同版全量/增量不会互相覆盖。
- `network.py`：严格验证 Range 206 和 Content-Range、可取消范围读取、ETag/Last-Modified、断点下载、大小/哈希验证、原子发布。
- `payload.py`：只解析 protobuf 清单和元信息，不重写分区解压算法；保留未知字段，用清单展示大小/操作/基线依赖。远程 ssut 暂存重排数据偏移，保留数据/镜像哈希。
- `engine.py`：两种引擎的参数与进度适配；基线预检；能力预检；独立临时输出；最终大小与 SHA256 核验；生成提取报告。
- `app.py`：PySide6 三页桌面界面，后台任务、取消、数据筛选、链接复制、在线/本地镜像选择。

## 历史目录限制

更新接口可返回“无可见更新”，并不意味着该机型不存在其他固件。地区、当前版本、组件、资格名单、服务器撤包都会影响结果。本工具持续累积本地记录，支持添加完整 OTA 种子，但不使用虚构的历史版本列表或补造推送日期。受限尝鲜/降级需要用户提供真实设备资格信息。
