# 增量包核对报告

核对日期：2026-11-14；设备 OPPO Find X7 Ultra（PHY110，CN）。

## 结论

**存在可获取的增量包。v1.0.1 只按手机当前版本的组件基线探测增量，漏掉了历史源版本对应的增量。** 这不是“该机型没有增量包”，也不是必须通过 root 才能获取。

本次通过普通 ADB 只读检查设备属性，未主动使用 root。官方历史全量包只按需取得不足 1 MiB 的 my_manifest 镜像，再读取其中 build.prop，取得与历史源 OTA 匹配的真实组件版本；没有伪造组件基线或刷写手机。

## 实际查询结果

| 请求源基线 | 模式与结果 |
|---|---|
| 当前 17.0.0.100 / H.10 | manual、client_auto、server_auto、taste 均返回 2004 / artifactV1Result is empty |
| 历史 14.0.1.302 / A.53，匹配的组件集 | 常规通道返回 14.0.1.790 全量包；没有将它误当增量 |
| 历史 16.0.10.500 / F.28，匹配的组件集 | taste 返回真实 17.0.0.100 增量包 |

当前系统基线无结果只能说明该源版本当前没有可见更新，无法证明其他历史源版本没有增量。

## v1.0.2 修复

- 当前设备和每份历史基线分别建立请求，始终使用对应的源 OTA、组件版本和 NV。
- 普通 ADB 连接自动积累公开固件组件基线；内置本次核验的两份 PHY110 国区公开基线。
- 增量查询加入此前遗漏的 server_auto 模式。
- 禁止将全量防查询回退中的 fake OTA 代入增量源请求，避免源 OTA 与组件不匹配。
- 修正历史增量基线标注，保留同版本全量/增量两条记录及可刷新查询配方。
- 填入 GUID 时保留公开 v3 增量请求，不让设备资格 v6 取代公开接口；公开包按公开接口刷新链接，且不存储真实 GUID。

修复后的完整流程进行了 45 个查询，自动取得上述增量包，并在日志中说明本轮查询覆盖的基线数量。历史基线和服务器保留范围仍有限，工具不宣称穷尽全机型的所有历史增量。
